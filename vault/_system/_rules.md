# Vault Rules

Every routine reads this file before touching anything. If a rule here conflicts
with a routine prompt, this file wins. If something is not covered here, the
routine stops and logs it. It does not improvise.

---

## 1. Org codes

Every note carries exactly one `org:` value. There is no "both" and no blank.

| Code       | Entity                          |
| ---------- | ------------------------------- |
| `gfai`     | Growth Factor AI (SaaS)         |
| `lgb`      | Lead Gen Ben (service)          |
| `nmma`     | Nashville MMA Training Camp     |
| `fbg`      | Fighters Boxing Gym             |
| `personal` | Personal life                   |
| `system`   | Vault infrastructure only       |

If a note genuinely spans two orgs, it belongs to the one that owns the money or
the decision. Note the other in `related_orgs:` and move on. Nothing is filed twice.

## 3. Naming

- Files are lowercase, hyphenated, prefixed by type:
  `client--compass-hp.md`, `offer--local-ai-search-v3.md`, `sop--ghl-onboarding.md`,
  `project--five-location-model.md`, `person--mahalia.md`
- Version numbers live in the filename for offers only. Everything else versions
  in frontmatter.
- Dates are `YYYY-MM-DD`. Always. No other format is accepted or written.
- Memory files are the one exception to the type prefix. They are named for their
  subject: `identity.md`, `stack.md`, `operating.md`, `gfai.md`.

## 5. Offer lifecycle

Offers are never edited in place once `offer_status: live`.

To change price, scope, term, or SLA:

1. Copy the file to the next version number.
2. New file: `version: n+1`, `supersedes: <old slug>`, `offer_status: live`.
3. Old file: `offer_status: sunset`, `sunset_date: <today>`. Body untouched.
4. Existing clients keep pointing at the version they bought. They migrate to the
   new version only at renewal, and only when a human says so.

A routine may create a sunset stamp. A routine may not author a new offer version.
Writing the new offer is a human job. The routine's job is flagging that one is due.

To retire an offer entirely: set `offer_status: sunset`. It stays in `offers/`
until zero clients reference it, then the month-close routine archives it.

## 6. Hard rules

1. **Never delete.** Move to `70-archive/<year>/` and stamp `archived: <date>` and
   `archived_by: <routine-name>`. This is what "delete" means everywhere in this
   vault. The one exception is a memory line the human asked to forget, which is
   removed outright per rule 9.7, because an archived copy of a forgotten fact is
   not forgotten.
2. **Never edit a note body.** Routines write frontmatter, move files, and generate
   files inside `_system/`. Prose in a note belongs to the human who wrote it. The
   exception is `_system/memory/`, which routine 6 owns outright and rewrites.
3. **Never cross the personal line.** No note in `50-personal/` may be read, moved,
   linked, or summarized by a business routine. No business note may be linked from
   a personal dashboard. No personal fact may land in `_system/memory/`, and no
   business fact may land in `50-personal/memory/`. This is enforced by folder
   allowlist and repeated here so it survives a prompt rewrite.
4. **Never co-brand across walled clients.** If a client note lists a slug in
   `never_link:`, no generated dashboard, rollup, index, or memory file may place
   those two names in the same file. Aeterna Club is never co-branded with Compass
   HP or with any gym client. Check `never_link:` before writing any multi-client
   output.
5. **Never invent taxonomy.** No new folder, no new `type:`, no new tag that is not
   already in this file or already used three or more times in the vault. No new
   memory file outside the fixed set in rule 9.2.
6. **Never guess a date.** Missing `renews:` is a `needs-human.md` line, not an
   estimate.
7. **One run, one log.** Every routine writes `_system/logs/YYYY-MM-DD-<routine>.md`
   listing every file touched and what changed. No silent runs.
8. **Commit or it did not happen.** Last step of every routine:
   `git add -A && git commit -m "routine: <name> YYYY-MM-DD"`.

## 7. Renewal ladder

The sweep computes `days_to_renew` from `renews:` for every client where
`client_status: active`. Buckets and actions:

| Bucket | Days   | Action                                                        |
| ------ | ------ | ------------------------------------------------------------- |
| T-60   | 53-60  | Dashboard row only. Flag whether the current offer is `sunset`. |
| T-30   | 23-30  | Create ClickUp task: renewal prep. Include offer version + health. |
| T-14   | 9-14   | ClickUp task priority up. Dashboard row bold.                 |
| T-7    | 1-7    | Dashboard "urgent" block at top. Log a warning line.          |
| Overdue| < 0    | Urgent block. If overdue > 14 days, flag `health: red`.        |

Task dedupe: one ClickUp task per client per renewal cycle, matched on title
`Renewal: <client> <renews date>`. Never create a second one.

If a client's active offer has `offer_status: sunset`, the T-60 row reads
"needs new offer version" so a replacement gets written before the conversation.

## 8. Ambiguity queue

`_system/needs-human.md` is append-only. Each line:

```
- [ ] YYYY-MM-DD | <routine> | <file> | <what is unclear> | <what it would take to resolve>
```

A routine adds lines. Only a human checks boxes. If the same file appears three
times, the routine stops adding and notes that the schema itself may be wrong.

## 9. Memory

Memory is not a transcript. It is the small set of facts that stay true after the
conversation that produced them is over. Routine 6 owns this section. Nothing else
writes to `_system/memory/`.

### 9.1 The horizon test

A candidate fact gets filed only if all four hold. If any one fails, it does not
get filed, and the reason goes in the log.

1. **Durable.** Still true a month from now.
2. **Portable.** Useful in a conversation that is not about the note it came from.
3. **A fact or a pattern.** Not an event, not a mood, not a status that a client or
   project file already tracks.
4. **Not already recorded.** Not present in a memory file, and not already carried
   by the frontmatter of a client, offer, project, or person note. Frontmatter wins.
   Memory never duplicates a schema key.

The test is a filter, not a scoring system. Three out of four is a skip.

### 9.2 The fixed file set

Nine files. Routine 6 may not create a tenth.

| File                        | Holds                                                      |
| --------------------------- | ---------------------------------------------------------- |
| `identity.md`               | Who Ben is, the five entities, slogan, mission, voice rules and banned words |
| `stack.md`                  | Tools and where each one sits: ClickUp, OpenClaw, GHL, WordPress, Hostinger, n8n, the agent roster |
| `operating.md`              | How Ben works. Standing instructions, decision patterns, what he wants asked versus assumed |
| `gfai.md`                   | Durable facts scoped to Growth Factor AI                   |
| `lgb.md`                    | Durable facts scoped to Lead Gen Ben                       |
| `nmma.md`                   | Durable facts scoped to Nashville MMA                      |
| `fbg.md`                    | Durable facts scoped to Fighters Boxing Gym                |
| `_candidates.md`            | Single-appearance facts waiting on confirmation            |
| `_superseded.md`            | Facts a newer fact replaced, with both dates               |

`50-personal/memory/personal.md` is the tenth store and routine 5 owns it. Routine
6 never opens it.

A fact that fits none of these files is a `needs-human.md` line. Routine 6 does not
pick the closest file.

### 9.3 Never filed

These are never written to any memory file regardless of what was said, how it was
said, or who said it. There is no flag, key, or prompt that turns this off. A
never-filed hit is logged by category name only. The content is not quoted in the
log, because a log is a file too.

1. Health or medical detail about anyone, Ben included.
2. Race, religion, politics, sexual orientation, or union membership, for anyone.
3. Credentials of any kind: passwords, API keys, tokens, card or account numbers,
   recovery phrases, client portal logins.
4. Client financial detail beyond the keys the client schema already defines.
5. A negative characterization of a named third party. Someone's competence,
   reliability, or character is a mood with a name attached, and it outlives the
   mood if you file it.
6. Anything read from `50-personal/`, ever, by any path.
7. Anything a human listed in `_system/memory/_forget.md`.
8. A one-off emotional state, on any subject.

### 9.4 First appearance

A passing mention is not a fact yet. On first appearance a candidate goes to
`_candidates.md`:

```
- <fact> | first seen YYYY-MM-DD | src: <path>
```

It gets promoted into its real file on a second appearance that is independent:
a different source file, or the same source on a different day. Promotion removes
the candidate line. A candidate that has not reappeared in 60 days is dropped and
the drop is logged.

Two things skip the holding pen and get filed on first appearance:

- A fact Ben stated directly as a standing instruction, preference, or correction.
  "From now on", "always", "never", "stop doing", "I use X for Y" are all direct.
- A structural fact that a client, offer, project, or person file already implies
  and memory is only naming.

### 9.5 Line format

Every memory line:

```
- <fact, one sentence, present tense> | first seen YYYY-MM-DD | confirmed YYYY-MM-DD | src: <path>
```

A pinned line, which a human wrote or locked:

```
- [pin] <fact> | pinned YYYY-MM-DD
```

Facts sit under headings inside each file. Routine 6 may re-sort lines under an
existing heading. It may not add a heading that is not already in the file.

### 9.6 Supersede, never overwrite

When a new fact contradicts a filed fact, the newer one wins and the older one
moves to `_superseded.md` with both dates and both sources. The contradiction is
logged. Nothing is silently replaced.

A new fact that contradicts a `[pin]` line is the exception. The pin stands, the
new fact is not filed, and the conflict becomes a `needs-human.md` line. A human
put that pin there on purpose.

### 9.7 Forget

`_system/memory/_forget.md` is human-owned and append-only by the human. Each line
names a fact, a subject, or a source to forget. On every run, routine 6 reads it
first, removes any matching line from any memory file outright, and never files a
match again. Removal here is a real removal, not an archive move, and the log
records that a forget rule fired without restating what was forgotten.

### 9.8 Loading

Memory is worthless if nothing reads it. The vault root `CLAUDE.md` imports the
business memory files, so any Claude Code session started in the vault has them at
turn one. `50-personal/CLAUDE.md` imports the personal memory file and nothing
else, which is what keeps a personal session from pulling client facts into view
and a business session from pulling personal ones.
