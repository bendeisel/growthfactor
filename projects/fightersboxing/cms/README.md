# The schedule CMS

The gym's weekly schedule lives in Sanity so the client can change a class
time in one place and every page on the site follows: the schedule page, the
kids block, and each class page. Nothing is typed twice and nothing needs a
developer.

This folder holds the parts that belong in the repo:

- `schemaTypes/classSession.ts` the shape of one class on the schedule
- `schemaTypes/index.ts` the schema list the Studio imports
- `seed.ndjson` the current 22 classes, ready to import in one command

The Studio app itself is generated by Sanity's own tool, so it always comes
with current versions rather than whatever was pinned here months ago.

## Setting it up, once (Windows)

Open a terminal in `projects\fightersboxing`.

1. Create the Sanity project and a Studio app next to this folder:

   ```
   npm create sanity@latest
   ```

   Answer: project name `Fighters Boxing Gym`, dataset `production`, template
   `Clean project with no predefined schema types`, output path `studio-app`.
   Say yes to TypeScript.

2. Copy the schema in, overwriting the generated placeholder:

   ```
   copy cms\schemaTypes\*.ts studio-app\schemaTypes\
   ```

3. Load the current schedule, from inside `studio-app`:

   ```
   cd studio-app
   npx sanity dataset import ..\cms\seed.ndjson production
   ```

   That creates all 22 classes as they are on the site today.

4. Put the Studio online for the client:

   ```
   npx sanity deploy
   ```

   Pick a hostname such as `fightersnashville`, which gives the client
   `https://fightersnashville.sanity.studio`. Invite them from
   sanity.io/manage with the Editor role.

5. Make the dataset public, at sanity.io/manage, so the website can read it
   without a token: project, then Datasets, then set `production` to public.
   It holds a class schedule that is already on the public website.

6. Tell the site which project to read. In `site`, copy `.env.example` to
   `.env` and fill in the project id from sanity.io/manage:

   ```
   PUBLIC_SANITY_PROJECT_ID=abc12345
   PUBLIC_SANITY_DATASET=production
   ```

   Set the same two variables in the host's build environment so deploys
   read the live schedule too.

## What the client does

They open the Studio, click a class, change the time, and press Publish.
That is it. The website picks it up on the next page load, and the next
deploy bakes it into the HTML.

Adding a class: Create, then fill in name, day, start time, who it is for,
and which pages it should appear on. Removing one: delete the document.

## Why it stays fast

- **Built in.** Every deploy reads Sanity and writes the times straight into
  the HTML, so the page is still a static file, still crawlable, and still
  correct with JavaScript switched off.
- **Live on top.** On load the page re-checks Sanity through its CDN and
  re-renders only if something changed, so a Publish reaches visitors right
  away instead of waiting for a rebuild.
- **Fails quietly.** No project configured, a bad request, an odd browser:
  the page keeps the times it was built with. The committed copy of the
  week in `site/src/data/schedule.js` is the floor under all of it, so the
  site can always be built by anyone who clones the repo.
